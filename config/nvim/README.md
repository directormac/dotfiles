# Neovim Configuration

A modular, high-performance Neovim configuration built with Neovim Nightly (0.13+), [`lze`](https://github.com/BirdeeHub/lze) + [`lzextras`](https://github.com/BirdeeHub/lzextras) for lazy loading, [`blink.cmp`](https://github.com/Saghen/blink.cmp) for completions, and Neovim's native `vim.lsp.enable` engine.

Provisioned hermetically via Nix using [`nix-wrapper-modules`](https://github.com/BirdeeHub/nix-wrapper-modules) in [`nixos/modules/apps/neovim.nix`](../../nixos/modules/apps/neovim.nix).

## Architecture & Lifecycle

### 1. Nix-to-Lua Bridge (`nixInfo`)
The wrapper generated by Nix injects a virtual module (`nix-info`) containing flake metadata, package paths, active categories, and wrapper settings.

In `init.lua`, this is initialized globally as `_G.nixInfo`:
- `nixInfo.isNix`: Boolean indicating whether Neovim is running inside the Nix wrapper.
- `nixInfo.has_cat(category)`: Checks whether a specific category or combination is enabled (e.g., `'lua'`, `{ any = { 'lua', 'nix' } }`).
- `nixInfo.get_nix_plugin_path(name)`: Retrieves the Nix store path of a plugin.
- `nixInfo(nil, 'info', 'flake')`: Flake revision and system architecture.
- `nixInfo(nil, 'info', 'plugins_meta')`: Upstream repository URLs, commit revisions, and versions for installed plugins.

### 2. Live Hot-Reloading Workflow
The Nix wrapper configures `config.settings.config_directory` using:
```nix
config.settings.config_directory = lib.generators.mkLuaInline
  "(vim.env.NVIM_DEV_CONFIG or vim.fn.stdpath('config'))";
```
Because Home Manager symlinks `~/.config/nvim` out-of-store directly to `~/.dotfiles/config/nvim`, any edit in this directory takes effect immediately in Neovim without needing `nixos-rebuild` or `nh os switch`.

## `lze` Handler Architecture

This configuration uses [`lze`](https://github.com/BirdeeHub/lze) extended with custom handlers:

| Handler | Spec Field | Description |
| --- | --- | --- |
| `handlers.opts` | `opts` | Automatically resolves options (table or function) and invokes `require(mod).setup(opts)` before running `after`. |
| `handlers.load_before` | `load_before` | Declares that this plugin must load *before* target plugin(s) load. Queues plugins and triggers them via `M.before(target)`. |
| `handlers.on_require` | `on_require` | Intercepts `require('<prefix>')` via `package.loaders` and lazily triggers plugin load on demand. |
| `handlers.rtp` | `rtp` | Sources `after/plugin` and `ftdetect` directories for opt plugins from `/nix/store`. |
| `auto_enable` | `auto_enable` | Disables specs if their packages are not installed in the current Nix configuration. |
| `for_cat` | `for_cat` | Conditionally enables plugins based on active Nix categories (`nixInfo.has_cat`). |

### Automatic `.setup(opts)` via `handlers/opts.lua`
When a spec defines `opts`, you do **not** need boilerplate `require('plugin').setup(opts)` calls in `after`. The handler:
1. Normalizes the plugin name (e.g. `'catppuccin-nvim'` → `'catppuccin'`, `'harpoon2'` → `'harpoon'`, `'gitsigns.nvim'` → `'gitsigns'`).
2. Evaluates functions or merges static option tables.
3. Calls `.setup(opts)` automatically.
4. Executes your custom `after(plugin)` hook for post-setup tasks (e.g. keymaps, toggles).

To bypass automatic setup for non-standard APIs, set `setup = false` or omit `opts`.

## Completions & UI Interaction (`blink.cmp` + `noice.nvim`)

### The Noice Completion Hijacking Fix
By default, `noice.nvim` enables `popupmenu.enabled = true`, which subscribes to Neovim's `ext_popupmenu` UI protocol. When Neovim triggers a popupmenu (such as during native completion, LSP trigger characters like `.`, or omnifunc), Noice intercepts the items and renders them in a centered floating window in the middle of the screen (`row = 8, col = '50%'`), getting in the way of editing.

To resolve this conflict:
```lua
-- lua/plugins/noice.lua
opts = {
  popupmenu = {
    enabled = false, -- Never hijack completion menus!
  },
  lsp = {
    signature = {
      auto_open = {
        enabled = false, -- Prevent signature popups from fighting with blink docs
      },
    },
  },
}
```

With `popupmenu.enabled = false`:
1. Noice will never attach to `ext_popupmenu`.
2. [`blink.cmp`](lua/plugins/completion.lua) manages completion menus exclusively, anchoring completion items and documentation popups cleanly right at the cursor position.
3. Command-line completion (e.g. `:`) is handled cleanly by `blink.cmp`'s native `cmdline` source.

## Language Server Protocol (LSP)

Language servers are registered natively in [`lua/plugins/lsp.lua`](lua/plugins/lsp.lua) using Neovim 0.11+'s `vim.lsp.enable(server)`.

- **Server Settings**: Merged from `lsp/<server>.lua` via Neovim's built-in `vim.lsp.config()`.
- **Keymaps & Attach**: Managed centrally in [`lua/lsp_handlers.lua`](lua/lsp_handlers.lua) on `LspAttach`:
  - `gd`: Goto Definition (via Snacks picker)
  - `gr`: References (via Snacks picker)
  - `K`: Hover documentation / Focus popup
  - `<leader>ca`: Code actions
  - `<leader>cr`: Rename symbol
  - `<leader>ss` / `<leader>sS`: Document / Workspace symbols
- **Diagnostics**: Styled with custom gutter signs, virtual text, and single borders in [`lua/diagnostics.lua`](lua/diagnostics.lua).

## Plugin Inspection Picker

Run `<leader>fp` or call `require('pickers.common').plugins()` to open the interactive `lze` plugins picker:
- Displays all installed plugins, their lazy/loaded state, load order, and active triggers.
- Shows Nix derivation metadata (upstream Git commit revision, date, repository URL, version).
- Allows toggling plugin details, inspecting source specifications, and verifying lazy-loading behavior.
